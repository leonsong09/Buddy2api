# Buddy2api v2.2.14

发布日期：2026-11-02

本次补丁版本汇总 [PR #129](https://github.com/wicm84266964/Buddy2api/pull/129) 的跨通道账号回退、余额调度及管理页改进，并补充 [Issue #130](https://github.com/wicm84266964/Buddy2api/issues/130) 涉及的 CodeBuddy / WorkBuddy 签到错误诊断。改动较多，升级前请阅读模型选择和余额恢复说明。

## 1. Chat 和 Responses 共用跨通道回退

旧版自动通道 Key 会先选定一个通道，再在该通道内换号。现在，请求裸模型名时会收集允许使用、能够识别该模型的账号，逐个尝试；首个通道失败后可以继续尝试其他匹配通道。`/v1/chat/completions` 和 `/v1/responses` 使用相同规则。

- **显式指定通道不会跨通道**：例如 `qoder/DeepSeek-Flash` 只会在 Qoder 内换号，全部失败后返回错误。
- **绑定通道的 API Key 不会越过通道限制**；只有允许自动选择通道的 Key 请求裸模型名时才可能跨通道。
- 每个候选分别检查模型白名单，避免某个通道获准后，另一个通道被一并放行。
- 一次尝试使用指定账号直到流结束；读取首包时发生异常，会释放失败的流并继续尝试下一个账号。已经开始返回的流不作透明重放。
- 没有 active 账号可服务时，保留尝试恢复过期凭据的路径。

## 2. 保留账号权重和用户偏好，增加通道顺序

调度先比较账号优先级，同优先级按配置的通道顺序，再按账号权重选择；同通道、同优先级和权重下尽量继续使用当前账号，需要重新选择时参考历史请求数和账号 ID。

- 管理页可调整通道顺序，并保留账号权重编辑和批量保存。
- 权重表示优先使用偏好，**不是按比例均分请求的承诺**。用户可以持续使用指定的高优先级或高权重账号，系统不会因到期时间、低余额或速率统计而强制分流。
- 增加账号顺位、路由预览、余额状态和到期信息，便于理解候选顺序。静态列表顺位和当前可用队列分别展示。
- 移除没有实际执行的速率、并发限制设置界面，避免把诊断读数误认为已生效的保护措施。

## 3. 不同通道的模型名称需要显式映射

模型原生 ID、大小写、日期、`x` 等后缀不会自动归一，也不会通过删除后缀推断模型等价。

例如 A 通道原生 ID 为 `model`，B 通道为 `model-x`：默认分别匹配；确认两者适合作为备用后，可在 B 通道配置 `model → model-x`，自动通道 Key 请求裸名 `model` 才能同时匹配它们。请核实模型版本和能力，别名映射由维护者配置，不代表系统验证了两个模型完全相同。

请求日志补齐客户端名称、实际通道和解析后的模型 ID，便于排查别名及回退结果。可用 `BUDDY_DEBUG_ALIAS=1` 开启别名解析调试。

## 4. 零余额暂停请求调度，签到继续

- 实测账号可花总余额 ≤ 0 时，不再用该账号承接普通模型请求，减少对空余额账号的重复尝试。
- **不把账号改成停用状态**：保持 active，仍可签到和保活。签到积累余额后，在账号页点击「额度」手动刷新；读到正余额后恢复调度。单纯切换启用状态不会清除缓存中的零余额。
- 零余额不会随缓存变旧自动恢复；未知余额继续允许尝试。余额查询超时或失败不写成推测的 0。
- 免费模型可按“通道＋模型”设置「忽略余额检查」，只跳过余额限制，不跳过账号状态和冷却检查。
- 账号页、仪表盘及上游拒付后的有效余额读取写回统一缓存；部分读取按字段合并，避免余额和到期信息互相覆盖。每日桶和单次签到奖励不冒充账号总余额。
- Qoder、千问办公签到中的到期信息保存供管理页展示；到期时间不参与调度排序。

## 5. API Key 日次数规则

在模型与权限检查通过、候选队列非空后，首次派发前原子预留 1 次日限额：

| 场景 | 日次数 |
| --- | --- |
| 一次请求成功 | 1 次 |
| 内部多次换号或跨通道后成功 | 合计 1 次 |
| 已开始尝试但所有上游最终失败 | 1 次，不退回 |
| 没有可用候选，直接返回 503 | 0 次 |
| Key、模型或请求参数校验失败 | 0 次 |

客户端自己重新发送的请求属于新请求，重新按上述规则计次。此规则按请求数计，不是 Token 数或账号积分。

## 6. 签到报错保留真实 HTTP 信息

此前签到接口返回空内容、HTML 或纯文本时，页面只显示 `Expecting value: line 1 column 1 (char 0)`，真实 HTTP 状态丢失为 0，难以判断原因。

现在区分“查询签到状态”和“领取积分”阶段，保留真实 HTTP 状态，并说明响应类型。例如：

- `查询签到状态：HTTP 200，空响应`。
- `查询签到状态：HTTP 403，HTML 页面，非 JSON；请求被拒绝`。
- `领取积分：HTTP 502，非 JSON 响应；上游或网络网关异常`。
- 网络异常显示失败阶段和异常类型，如 `ConnectError`，而不是混同于 JSON 解析失败。

不展示原始响应正文、重定向地址或请求凭据。**这些诊断能缩小排查范围，但 401/403 仍可能涉及登录状态或上游访问限制，不能仅凭状态码断言根因。** 本地真实账号重试返回 HTTP 200、今日已领取，尚未复现 issue 作者的实际失败；本次修复改善诊断，不声称已经恢复所有环境下的签到。

自动签到与手动一键签到共用 `checkin_all → claim_one → claim_daily_checkin` 的请求逻辑，均会实时查询状态后再领取。自动任务每天触发一次，失败后当天不会自动补试；手动点击会重新请求。本地日志中确有自动签到 HTTP 500、稍后手动领取 HTTP 200 的情况，属于不同时间的上游返回，不能据此认定两条路径采用不同接口或登录态失效。本版本未改变自动任务的重试策略。

## 7. 其他兼容性和管理页改进

- 保留 WorkBuddy 的客户端提示词兼容处理：通用 system 提示、客户端 system 指令搬入用户消息及已知身份词处理，以减少上游“非官方渠道”拒绝。这会改变指令在上游的角色位置，有自定义 system 指令的用户请验证输出格式及工具调用。
- 小浣熊增加会话有效性探测和客户端凭据重读，修复重读缓存不会到期的问题；余额接口的 429/5xx 不再直接判为登录失效。
- TraeWork 兼容更多客户端登录目录名称。
- Vue 改为本地依赖，管理页不再依赖外部 Vue CDN；新增模板编译及脚本语法检查。
- 本版本不包含客户端多开、设备身份生成或新增的一键启动脚本。

## 升级与兼容性

1. 建议先备份现有数据库及配套密钥文件；数据库和密钥文件一起保留，不要公开上传。
2. 更新代码或镜像，重启服务，刷新管理页。数据库新增字段在启动时自动迁移，保留账号、Key 和原有权重。
3. 检查通道顺序及跨通道别名配置；要固定通道，请使用 `通道/模型` 或绑定通道的 Key。
4. 余额已耗尽的账号在签到积累后，手动刷新「额度」恢复调度。
5. 旧 `routing_factors` 配置被忽略。原 `403 key_channel_mismatch` 改为 `400 model_not_allowed`；模型／通道名称错误返回对应的 400 错误码。依赖这些状态码的客户端请同步调整。

Docker 正式镜像为 `ghcr.io/wicm84266964/buddy2api:v2.2.14`，平台 `linux/amd64`；发布工作流构建成功后同时更新 `latest`。推荐固定版本标签。
